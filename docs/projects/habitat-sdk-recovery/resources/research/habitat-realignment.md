## The Decision

Keep the valuable substrate foundation. Do not roll it back wholesale, restore
the rejected ledger work, or restart from the older borrowed specification.
Correct the target and its delivery dependencies before adding live runtime.

The important frame change is from completing a historical sequence of
specification packets to delivering capabilities that preserve meaning from
authoring through actual execution. Receipts and passing tests remain evidence;
they do not make an incidental constraint correct or a capability finished.

## What Changed

**One current authority path.** The architecture, detailed runtime specification
and active OpenSpec now agree on their respective jobs. Mixed historical bodies
were preserved intact outside active discovery. There is no new competing set
of specifications and no requirement to reconstruct current instructions from
old task receipts.

**Five fundamental corrections.** Named service dependency assignments must
survive planning and affect parent identity. A process checks its own selected
dependency closure, not unrelated app roles. Services carry a complete cold
construction export. Derivation owns semantic normalization once; compilation
lowers its cohesive handoff. Private boot ordering validates trusted data rather
than promising to sandbox arbitrary hostile JavaScript objects.

Required configuration sources remain required. Their ordered declarations now
explicitly cross compilation even when no selected value refers to them. This
prevents the simplified handoff from silently losing startup policy.

**Executable policy now permits sensible implementation.** Four complete
immutable successors allow private TypeScript helpers and test support while
still enforcing ownership, assembly, package and source-language boundaries.
They were exercised through an installed SDK/CLI consumer. All 98 earlier
blueprint files remain byte-identical.

**The work is accounted for honestly.** All 115 inherited task IDs retain their
original state and have a disposition. The current runtime queue has 49
unchecked acceptance obligations, including two explicit repairs. This is not
a completion percentage. Review also found and assigned spec-level agent,
desktop and web-local authoring promises that task counting alone had missed.

**Optional integrations no longer block everything.** Ledger, inquiry, later
Rawr transfers and actual native agent/desktop hosts have separate, durable
reactivation and acceptance conditions. Their promised behavior was preserved,
not marked done or quietly weakened. Agent/desktop authoring remains required
in the core runtime; functioning authoring APIs are not proof of native hosts.
An external Fluree maintenance commitment still requires separate authority.

## What Was Not Done

No live runtime source was implemented. The known cold-pipeline and bootgraph
code still needs the newly specified repair. No SDK/CLI package was published,
consumer migrated, old task resumed, hosted infrastructure changed, historical
worktree cleaned or rejected stash restored.

Civ7 and Magic remain independent consumer work. Civ7's older missing-service-law
gate is stale because released 0.5.15 supplies foundation service law, but its
native migration and V8 acceptance are still its own work. Magic's staging and
product acceptance are not evidence of Habitat adoption.
