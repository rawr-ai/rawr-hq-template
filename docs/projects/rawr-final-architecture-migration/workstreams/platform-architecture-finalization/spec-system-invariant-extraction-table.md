# RAWR Specification System Invariant Extraction Table

Status: DRA-synthesized extraction table for the Platform Architecture Finalization workstream.

Purpose: preserve the source anchors behind the standalone **RAWR Specification System** companion specification. Rows are evidence candidates until accepted by the DRA. The final specification may compress or combine rows, but every normative rule should trace back here or be explicitly marked as DRA synthesis from named evidence.

## Status Legend

| Status | Meaning |
| --- | --- |
| `normative-current` | Current repo authority or workstream-settled direction. |
| `harvest-candidate` | Useful `_inbox/latest` or planning-language candidate; requires owner and placement before use. |
| `reserved` | Intentionally not final, but named with owner, contract/hook, and lock trigger. |
| `deferred` | Valid follow-up outside this workstream; must name owner/future DRA and trigger. |
| `stale/provenance` | Historical or external material; can explain history but cannot decide current authority. |
| `conflict-needs-DRA` | Source tension requiring DRA judgment or user escalation. |
| `candidate` | Implicit convention with support, but not yet elevated to a mandatory corpus rule. |

## DRA Synthesis Notes

- The final spec makes exactness metadata mandatory for diagrams, generated examples, schema excerpts, code/type excerpts, and contract tables where illustrative material could become accidental authority. It does not require the full runtime-spec metadata pattern for every prose paragraph.
- `_inbox/latest` has the clearest formulation of deferral-vs-gap and hub-language improvements, but it remains a harvest source. Rules from it are elevated only where supported by the prompt, integrated plan, current platform spec, runtime spec, or DRA synthesis recorded here.
- Runtime mechanics named in this table are evidence anchors. They should not be copied into the spec-system document as mechanics.
