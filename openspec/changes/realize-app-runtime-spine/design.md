## Context

At the recovery baseline `374149800a067e527342e334ff6a3022fbd38cd7`, Habitat
implements schema, definition, derivation, compiler and bootgraph owners.
The other five private runtime owners are not implemented. Source contains
unreleased runtime SDK faces; released 0.5.15 is a foundation artifact, not the
finished runtime. Existing checks are real baseline evidence, not proof of the
new target or deployed consumers.

The old plan mixed semantic law, exact edit inventories, review receipts and
current task routing. It also made generic provisioning wait for semantic-ledger
vendor qualification. Clean successors now occupy the same active paths, with
intact originals outside native OpenSpec discovery. Every inherited obligation
has a disposition; completed history is not rewritten as new work.

## Goals / Non-Goals

Realize the full seven-phase runtime with reusable owner boundaries, real native
behavior, process-local lifetime, safe failure handling, observability and
installed consumer acceptance. The unit of delivery is an operating capability,
not another collection of declarations or an arbitrary source count.

Do not restore old mixed owners, introduce a compatibility runtime, implement
downstream products in Habitat, add an app-owned service implementation registry,
publish internal runtime packages, or substitute a custom vendor execution engine.
This preparation changes authority and executable policy only; live runtime
source work starts with task 0.1 in a subsequent implementation pass.

## Decisions

### One Meaning-Preserving Cold Pipeline

Derivation owns authoring normalization: the selected process closure, effective
scope/config, dependency slots, instance convergence and provider coverage.
Compilation lowers that admitted result rather than independently reproducing
the binding algorithm from a caller-paired entrypoint and graph. Keep data-only
graph inspection and external serialized-data schema validation. Executable
compilation requires the actual cohesive derivation-owned handoff with exact
cold references, not an arbitrary imported graph or an authenticity registry.

Services selected for runtime use expose one complete service-owned cold join
of declaration, canonical callable contract and typed synchronous constructor.
Seal it at the public service boundary after the native implementation exists;
do not make the upstream declaration import its own router. Constructors receive
ready declared dependencies and decoded scope/config. They acquire nothing,
execute no Effect, and capture no invocation. Preserve the native oRPC contract
and official Effect bridge; a Promise-client alias is not a managed Effect view.

The selected nonportable reference channel crosses derivation and compilation
explicitly into process runtime. It is separate from portable graph data and
provisioned resource values. Runtime must not recover implementations through a
service-id registry, private imports or the original authoring tree.

### Names Survive Instance Selection

Coarse topology is a set projection for reachability and cycle checks. Different
dependency slots may reach the same service or resource without becoming
duplicate author declarations. The executable recipe preserves named dependency
assignments, including `localName -> child bindingId`; those assignments affect
the parent's identity. A sorted child-id set alone loses meaning.

Equal complete requests for one role-local service identity and optional instance
reuse one binding. Divergent requests refuse before acquisition. Explicit
nonempty opaque case-sensitive instance names select different identities even
when current config happens to match. Plugin injection names alone do not split
the child's cache. Invocation and decoded object identity are not cache inputs.
Keep selected-cycle and conflicting-definition/complete-export refusal.

### Startup Selects A Process, Not The Whole App

Determine the selected process's role/surface roots and transitive service,
resource and selected-provider closure before coverage and value preflight.
A profile may be a reusable superset; unused provider selections, dependencies,
config refs and builds remain inert. Missing or ambiguous selected coverage
refuses before acquisition. Whole-app inspection remains a separate tool.

This does not weaken source policy: a selected profile's explicitly required
config sources remain required, and first-hit lookup fails closed on a winning
decode failure. Only selected provider/service values are resolved and decoded.
Imported malformed declarations or module initialization are not isolated by
this rule.
The compiled handoff carries the profile's ordered source declarations as data
even when there are zero selected value refs. This is required for later
preflight without a hidden lookup into the original profile.

### Private Cold Data Has An Honest Trust Boundary

Boot ordering consumes compiler-owned in-memory data, not arbitrary hostile
executable JavaScript. Retain shape/relation validation, dangling/duplicate/cycle
refusal, deterministic dependency-first ordering, reverse release/rollback,
immutable output, input non-mutation and zero declared executable calls.
Retire the exhaustive zero-trap Proxy/prototype protocol and prescribed
introspection algorithm. External config, manifests, paths and serialized
artifacts retain their actual validation and containment requirements.

### Native Runtime And Lifetime

Retain the canonical owner graph, seven phases, five service context lanes,
process launch identity and native callable rules. One Effect managed runtime
owns one process's acquisition scope and finalizers. Force context before mount.
Do not turn the bootgraph into an Effect Layer graph or services into Effect
service nodes. Binding uses ready dependencies; native hosts retain their
execution/cancellation semantics.

Mounting alone coordinates native-stop-before-provider-release across owners.
Deadlines report unsettled native work truthfully and do not authorize forced
release. Sibling processes keep separate resources, health, native handles and
stop operations. Observation projects evidence and cannot choose behavior or
replace the primary outcome.

### Policy Protects Ownership, Not First-Draft Layout

Private runtime owners stay package-less, positively closed and independently
verifiable. Complete immutable successors permit owner-local TypeScript helpers
and tests without freezing the initial source inventory. Required project
anchors, the private assembly entry, public SDK boundary and real Nx edges
remain enforced. Old closures and package-byte proofs stay intact.
No unpublished-version exception, open-scope escape or extra package is needed.

New owners co-land their conforming selected law, implementation, schemas,
router, real source/build edges and scheduler targets. Use the repository's
existing Nx contract: shared lint; cacheable typecheck/test/build and applicable
verify/policy; non-cacheable aggregate check; test/build explicit in CI.
Each newly created owner proves unchanged-cache restoration and relevant-input
invalidation. Grit, Habitat, Nx, TypeScript and behavioral tests retain their
different responsibilities.

### Capabilities Have Their Own Prerequisites

Generic provisioning needs accepted resource/provider plans, not a Fluree
implementation. Ledger and temporal inquiry retain their provider-neutral intent,
unrestricted merge and qualification obligations in [deferred-capabilities](deferred-capabilities.md).
No core release claims those faces before they are implemented and verified.
A Rawr workstream that requires ledger still waits for it; unrelated consumers do
not. Vendor qualification resumes from current published artifacts and evidence,
not the old assertion that an owned fork is the only option.

The existing SDK/CLI release pair and exact-main installed-artifact barrier remain.
There is no permanent limit of two functional releases. A later optional
capability release cannot retroactively change an earlier receipt. Consumer
adoption, product acceptance, historical source retirement and platform release
are separate events with explicit dependencies.

Agent and desktop authoring are not deferred along with unsupported native
hosts. Task 10.1 delivers their canonical projection, executable and schema
faces with real descriptor-to-process execution proof; tasks 14.1/14.2 deliver
web-local executable authoring without conflating it with route-module loading.
Actual agent/OpenShell and desktop host integration retains its native contracts
in D-4, with selected-host qualification, security and real lifecycle acceptance.
This explicit delivery separation closes a missing spec-level obligation; it
neither publishes empty exports nor claims every canonical native host is done.

## Risks / Trade-offs

### Native Server Realization

Tasks 13.1 and 13.2 co-land one complete native server story: the cold Elysia
companion, selected private source handoff, native OpenAPI/public and RPC/internal
handlers, original-request context, native Effect bridge, real graceful drain
and provider-owned native telemetry. The accepted cohort is Bun 1.3.14,
Elysia 1.4.30, Effect and Effect OpenTelemetry 4.0.0-beta.101, and oRPC
2.0.0-beta.32. This does not add a new SDK host selector or registration model.

Public documents use native contract projection before synthetic router
aggregation so default paths remain identical to the served paths. Internal
routers remain absent from publication; the host refuses cross-owner route
collisions rather than silently accepting first-handler shadowing. Distinct
host descriptors replicate selected surfaces, while the same descriptor
cohosts its registered lanes. Native router semantics within a surface remain
native-owned.

The composed server fixture belongs to the terminal SDK test owner and runs
under Bun through both native harness acceptance targets. It is not a private
runtime import of the SDK. A real local OTLP receiver proves transmission and
request/Effect trace lineage in ordinary tests. It deliberately does not claim
collector processing or backend persistence/queryability. Those and product
wide-event cardinality remain full-observability qualifications, not reasons to
add Podman startup to the server's ordinary deterministic acceptance.

The cold pipeline correction spans definition, derivation and compiler because
their shared meaning is the defect. Splitting it into nonconforming law-only or
half-plumbed source nodes would preserve a false green state. Task 0.1 is one
complete cold story with narrowly scoped integration proof; native acquisition
and live binding remain later stories.

Deferred capability history is large. Its intact archive is provenance; the
current deferred record preserves the essential promises and reactivation
criteria. It is not a second active implementation queue. Semantic-ledger
qualification failure must not be quietly reclassified as success or weaker
merge capability.

Vendor pins in canonical contracts are accepted mechanisms, not claims that
those versions are the newest. Implementation must read the installed/pinned
source before touching each native boundary and requalify a deliberate upgrade.
No vendor dependency or external artifact changes in preparation.
